<AnswerBox>
Topshe is a voice assistant that never calls home. Named after the teenage assistant in Satyajit Ray's Feluda stories — the one handed the research, the planning, and the grunt work — it runs wake word to speech-to-text to a quantised Qwen 2.5 LLM inside the browser over WebAssembly. No server, no API key, no data leaving the phone.
</AnswerBox>

Most people assume a voice AI assistant *must* phone a cloud. For Topshe, the entire stack runs locally: React 19 shell, Web Speech API for input, a quantised Qwen 2.5 1.5B Q4 model inferring through **WebAssembly (via `wllama`)**, offline-capable as a PWA. The whole binary is ~900 MB cached in IndexedDB — you download it once.

## Was he in the Feluda stories?

Yes — he was the one who did the work. Topshe is **Tapesh Ranjan Mitter**, the teenager Satyajit Ray's detective Feluda hands the random jobs to: go recognise the professor's handwriting, fetch the passport photo, keep notes on every suspect, draft the plan for tomorrow's stake-out. Feluda thought; Topshe researched, planned, and kept records. That division of labour is exactly what this app is — a junior detective you can shout random tasks at, who quietly researches, plans, and remembers.

## What the real Topshe took as his tasks

- **Research** — WebSearch, weather, stock, and news tool handlers; ask for the current Sensex or tomorrow's forecast, no server call.
- **Plan** — todos, reminders, focus timer, and alarms with voice snooze; a "today plan" list greets you in the morning.
- **Records** — calendar and email via OAuth, conversation history in IndexedDB, and a simple RAG embedding pipeline so "remember that" persists on-device.
- **Registry** — every capability hangs off a tiny tool-registry event bus rather than a server route.

The repo is public: [github.com/saswatasg/topshe](https://github.com/saswatasg/topshe). Ten commits in, the personality system, contacts, clipboard, files, and REPL shipped to make the assistant's "random tasks" land somewhere.

## The pipeline, end to end

1. **Wake word** — Picovoice Porcupine (WASM) runs continuous keyword spotting on the audio stream. "Topshe" triggers; ~50 ms latency on device.
2. **Speech-to-text** — Web Speech API (browser native) or Whisper.cpp WASM fallback. Streaming partials feed the LLM as you speak.
3. **Intent parse + tool dispatch** — the quantised Qwen 2.5 1.5B Q4 (~900 MB, `wllama` runtime) receives the transcript, decides if a tool is needed, emits a structured call.
4. **Tool registry** — a 200-line event bus maps tool names to handlers: `web_search`, `weather`, `stocks`, `news`, `calendar`, `email`, `todo`, `reminder`, `timer`, `rag_remember`, `rag_recall`. Each handler is pure client-side or OAuth-to-your-own-accounts.
5. **Response synthesis** — the model composes a natural-language answer from tool results.
6. **Text-to-speech** — Web Speech Synthesis or Piper WASM for offline TTS.

No network hop. No API key. The only bytes leaving the device are your explicit OAuth grants to Google/Outlook calendars.

## Why edge, really

- **Privacy without a story.** Nothing leaves the device — no transcripts recorded by a vendor, no telemetry, no "improve the model" checkbox.
- **$0/month** with real inference, not an API token funnel. You own the compute.
- **PWA** — works as an app, no install, offline capable. Install to home screen, runs in airplane mode.

## The agent personality system (the v2 leap)

Version 1 was a tool-caller. Version 2 added a **personality system** — a small system prompt plus a few-shot memory block that persists across sessions in IndexedDB. The assistant now:

- Remembers your name, preferred name for it ("Topshe" / "assistant"), and tone preference (terse / conversational).
- Maintains a "running context" of the last 5 turns compressed into a summary, so "remember that" works without blowing the context window.
- Has a REPL mode — type `/` to drop into a raw prompt sandbox for debugging tool calls.
- Exposes contacts, clipboard, and file read/write (via File System Access API) as tools, so "send this to Anirudh" or "save this as a note" work end-to-end.

This turned "a voice tool" into "an agent you talk to daily." The personality system is ~300 lines of prompt + storage logic — small enough to audit, big enough to feel like a consistent character.

## The honest tradeoffs

- **Model size vs quality.** Quantisation shaves latency but taxes clever summarisation; the assistant is snappier than deep, by design. A 7B model would hallucinate less but wouldn't fit on many phones in-browser.
- **Memory ceiling.** Not every mobile device runs a 7B model comfortably in-browser; we size the model to the device (auto-detect RAM, pick 1.5B or 3B).
- **Wake-word environments.** WASM audio wakes fast in quiet rooms; speaker noise, AC hum, and cafe chatter still puzzle it. Porcupine helps but isn't magic.
- **OAuth is the only cloud.** Calendar and email need your explicit grant. If you don't connect them, those tools simply don't appear — graceful degradation.

## What it demonstrated

Edge LLMs are production-viable for **small systems with clear intents** — a light assistant, a noise tool, a vault-adjacent copilot. They are not (yet) full cloud-grade chat without a compute fallback.

The [recruiter-agent post](/blog/ai-recruiter-agent-build) and Topshe bookend the same taste: I keep reaching for the smallest system that gives the product to the user. Topshe is the smallest.

## What I'd do differently

- **Ship wake-word tuning** before claiming "hands-free" — the demo works, the hallway doesn't.
- **Benchmark on a mid-tier phone.** We demoed on silicon that flattered the WASM numbers; a Snapdragon 7-series shows 2–3× latency.
- **Build a WASM Whisper fallback** for STT when Web Speech is unavailable (Safari, some Androids).
